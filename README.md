# Handover · 新院区总务交接班数字化系统

把总务科交接班从纸质单据搬到手机上：移动端优先的 H5 交接班页面，部署于医院内网，支持离线填写、用量自动计算、阈值预警、逐项确认与电子签名、全程审计留痕。

**当前阶段**：M0 地基建设期——文档与交互 Demo 已就绪并经总务科多轮拍板；正式开发已于 2026-09-01 启动，TK-01（monorepo 脚手架）已完成。

## 仓库结构

```
demo/   交互 Demo（纯静态 HTML，浏览器直接打开即可体验，无需构建）
docs/   全部设计文档
scripts/  一致性校验脚本（node scripts/check-ledger.mjs）
apps/   正式代码（TK-01 起）：api（NestJS）、h5（师傅端 Vue3+Vant）、admin（科长后台 Vue3+Element Plus）
packages/  共享包：shared（三端共享类型与错误契约，TK-03 充实）
tests/  e2e（Playwright 用例，随 TK-31 建设）
```

开发环境一条命令启动（需 Node ≥20 + pnpm）：`pnpm install && pnpm dev`——后端 :3000、师傅端 :5173、科长后台 :5174。

## 当前状态

**已定案**（2026-08-31）：

- 技术栈：TypeScript 全栈，NestJS + Drizzle + MySQL 8.0（决策 D-T01，信息科运维顾虑已闭环）
- 液氧两时点读数自动记录实际测量时刻，名义时段仅用于卡片组织（DATA-13）
- 液氧夜间用量跨记录自动计算，换罐日跳过并标注"当日换罐"（F3-05）
- 报错必须点名缺失字段并支持点击跳转定位（C-09）

**待确认——总务科/科长**（详见台账"待确认清单"，按优先级）：

1. 液氧计量单位现场核实（DATA-12，阈值/用量/预警数值全局联动）
2. 压力类预警初始区间（F4-04、F4-06）
3. 月报导出格式（F5-04）、照片留存时长与调阅权限（DEP-03）、肺功能气体满瓶基数（DATA-06）
4. 历史纸质交接单是否迁移录入、录多深（可追溯率口径，DEP-11）

**待确认——信息科**（详见技术方案 §9）：

- 是否对接院内统一账号体系（当前按独立账号体系设计，预留对接位）

## 编号体系与纪律

两套编号贯穿全部文档，是引用与追溯的唯一索引：

- **规格编号**（台账）：`C` 原则（9 条）、`F1`–`F7` 功能规格、`ELE` 电梯专题、`DATA` 数据字典、`DEP` 部署度量，共 108 条；测试用例编号 = 规格编号 + `-T序号`（如 F2-08-T1），已在测试用例清单展开 80 条 + 18 条骨架，Playwright 用例库与台账一一对应
- **决策编号**（决策记录）：`D-P` 产品、`D-T` 技术、`D-M` 流程
- **任务编号**（任务分解）：`TK-` 前缀，39 个任务组织为 M0–M5 六个里程碑 + Phase 2 骨架
- **埋点事件**（埋点与度量清单）：`EVT-` 前缀，6 个事件，配套 telemetry_events 表建议（待采纳）
- **一致性校验**：`node scripts/check-ledger.mjs`——校验规格编号唯一、前缀计数、用例挂钩、任务数与文档链接；**修改任何带编号的文档后运行，红了就是改漏了**

**编号只增不复用**：作废的规格保留编号并标"(已废弃)"，作废的决策保留编号并标 ⛔；各文档的修订记录只追加、不删除。
