# Handover · 测试用例清单（v0.1）

- **定位**：台账铁律 3"测试用例以编号挂钩"的落地——把"验收方式 = 自动用例"的规格逐条展开为**用例索引**。用例编号 = 规格编号 + `-T序号`（如 F2-08-T1），Playwright/用例库与本表一一对应，即技术方案 §8 的"需求即测试"映射表。
- **上游文档**：《规格编号与验收对照表 v1.3》（规格与验收方式来源）、《PRD v0.2.8》（Given/When/Then 原始出处）、《API 契约 v0.1》（409 确认协议与错误结构）
- **层级定义**（对齐技术方案 §8 三层体系）：
  - **单元**：纯函数（Jest）——用量计算、预警求值、防呆判定、电梯预期计算
  - **接口**：API + 状态机 + 权限（supertest）——提交/撤回/异议/确认流转、后台管理
  - **E2E**：Playwright 模拟真实手机浏览器全链路，含**断网注入**（离线场景）
  - **定时**：服务端定时任务，用例以**时间注入**触发扫描（不真实等待）
- **与 Demo 状态的关系**：台账"Demo 状态 ✅"仅指 demo HTML 验证过交互逻辑；正式系统**仍须逐条实现本清单用例**，以本清单状态为准。
- **生成时间**：2026-09-01
- **状态**：v0.1——Phase 1 用例 80 条全部展开；Phase 2 用例 18 条为骨架（⏸），启动前按同一格式细化

**用例状态**：⬜ 未实现｜✅ 已实现且绿｜❌ 实现但红（阻塞发布）

## 运行纪律

1. **全量回归**：每次提交自动执行全部已实现用例（技术方案 §8），报告随任务归档
2. **状态回写**：用例转绿后回写本清单状态列，并联动台账对应规格行——"未勾完的模块不发布"以台账+本清单双确认为准
3. **新增用例**：同规格新场景续 `-T` 序号；规格作废则其用例保留编号标废弃，与台账纪律一致
4. **时间注入**：所有"定时"层级用例不真实等待，扫描任务的时间参数可注入/可配置
