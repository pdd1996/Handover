## 一、这张表为什么存在（60 秒版本）

规格驱动开发（SDD）的核心纪律：**文档是唯一事实来源，代码只是文档的派生物**。落到本项目：

1. 每条业务规则有且只有一个编号，编号回指 PRD 章节——任何人问"这条逻辑哪来的"，30 秒内能翻到出处；
2. 每条规格标注"现在走到哪了"（已设计？demo 已验证？口径待确认？），进度一目了然；
3. 变更纪律：**先改 PRD → 再更新本表 → 最后才动代码**，三步顺序不可颠倒；
4. 验收时逐条勾验，没有全部勾完的模块不能发布。

**三条铁律**：

1. **编号只增不复用**：某条规格日后作废，保留编号并标"(已废弃)"，防止历史引用断链；
2. **新需求 = 新编号**：修改已有规格须在"修订记录"追加一行说明改了什么、为什么；
3. **测试用例以编号挂钩**：用例编号 = 规格编号 + "-T序号"（如 F2-08-T1），Playwright 用例库与本表一一对应，即技术方案 §8 所述"需求即测试"。
