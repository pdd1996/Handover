# Handover · 任务分解（v0.2）

- **定位**：把台账 108 条规格拆成**有序可执行的任务队列**——每个任务挂规格编号、写明完成判据与依赖，作为开发（人或 AI）的工作队列。台账写"要什么"，本表写"按什么顺序做、做到什么程度算完"。
- **上游文档**：《规格编号与验收对照表 v1.4》（范围与判据来源）、《技术方案与数据库设计 v0.2》（实现方式）、《测试用例清单 v0.1》（完成判据的用例索引）、《API 契约 v0.1》（接口边界）、《双轨比对操作规格 v0.1》与《手工验收与运营检查单 v0.1》（TK-32/33 验收工具）
- **编号规则**：`TK-` 前缀 + 序号，与规格/决策编号同纪律——**只增不复用**，作废保留编号标"(已废弃)"；执行顺序以表中排列为准，调顺序不改编号
- **完成判据的统一口径**：任务完成 = ① 关联规格的全部 `-T` 用例绿（见测试用例清单）② 台账对应规格行状态回写 ③ 涉及表结构/口径的改动在技术方案修订记录追加一行
- **生成时间**：2026-09-01
- **状态**：v0.2，按台账 v1.4 与 DEP-05/06 拆解；Phase 2 任务为骨架（⏸），启动前细化

**状态符号**：⬜ 未开始｜🚧 进行中｜✅ 已完成（用例绿 + 台账已回写）｜⏸ Phase 2 骨架
